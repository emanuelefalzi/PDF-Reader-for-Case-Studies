# PDF Reader for Case Studies

A native macOS app for studying long PDFs (business case studies, reports, textbooks) side by side with Claude.
The original PDF stays in the centre. Next to it, Claude writes a simplified, faithful rewrite that scrolls in sync with the page, marks the key concepts on the original, builds a chapter index and concept maps, and answers questions with page citations.

> Internally the app is called **LelePdf**: that is the name you will see in the code, the Xcode target and the bundle.
> This repository is the public, English-language copy of a personal project I use every day for my master's degree.

## Why it exists

A normal PDF reader lets you read and highlight. When I study a 70-page case or report, what I actually do is read a page, struggle with a dense paragraph, paste it into a chatbot, lose my place, and repeat.
This app removes the copy-paste loop. Reading and studying become one activity on one screen:

- **Left sidebar:** page thumbnails, a real chapter index (generated by Claude when the PDF's own outline is missing or useless, editable by hand), and concept maps per chapter and for the whole book.
- **Centre:** the original PDF, untouched, with four kinds of marks drawn on top, chosen by Claude or added by hand, plus free annotations (highlighter, shapes, text boxes, notes) in the style of macOS Preview.
- **Right:** a plain-language rewrite in the PDF's own language, organised in cards per block. The two sides scroll together, and hovering a marked term lights up the same term on the other side.
- **Floating chat:** ask anything about the document. Answers cite clickable pages and flag anything that does not come from the PDF.
- **Export:** Markdown (Obsidian-friendly), Word with your own style template, PDF, or plain copy.

Everything that is generated or edited is saved locally and comes back when the PDF is reopened, even if the file was renamed or moved: documents are recognised by a fingerprint of their text.

### The four marks

Each document uses one subject colour; marks differ by shape and shade:

| Mark | Meaning |
|---|---|
| ▬ Filled rectangle | concept, thing |
| ◯ Empty circle | who or how much: actor, number, date |
| ___ Underline | action, decision |
| ___> Underline with arrow | consequence, effect |

## Tech stack

- **Swift 6** with complete strict concurrency, **SwiftUI** + **AppKit**, **PDFKit**, CryptoKit. Apple frameworks only, no third-party dependencies.
- **Claude through the local Claude Code CLI** (`claude -p`), using the user's own subscription instead of an API key:
  - one-shot calls with a JSON Schema and `structured_output` for analysis, rewrites, marks and the index;
  - a long-lived `stream-json` process for the chat, with token-by-token streaming, rate-limit events and context-budget summarisation.
- **XcodeGen** (`project.yml`) to generate the Xcode project; shell scripts for build, test, run and install.
- A **fake Claude CLI** ([`scripts/fake-claude/`](scripts/fake-claude/)) so the whole test suite runs offline and deterministically: it simulates success, invalid JSON, timeouts, logged-out users, rate limits and chat streaming. Real calls only run with `LELEPDF_REAL_CLAUDE=1`.

## Engineering highlights

- **Text pipeline on raw PDFs.** PDFKit text is messy: spaced-out running headers ("T H E F U T U R E"), words hyphenated across lines, duplicated glyphs, exhibits and footnotes. [`LelePdf/TextPipeline/`](LelePdf/TextPipeline/) cleans it, detects headings, paragraphs, headers/footers and exhibits, and segments the document into blocks sized for Claude.
- **Grounded marks.** Claude returns marks as exact quotes; [`MarkMatcher`](LelePdf/Analysis/MarkMatcher.swift) finds each one back in the page text and turns it into PDF geometry, so nothing is drawn where the text does not exist.
- **Linked scrolling.** [`LelePdf/Sync/`](LelePdf/Sync/) builds an alignment between PDF positions and rewrite rows and drives the two scroll views in both directions without feedback loops.
- **Safe persistence.** Atomic JSON writes with backups, a text fingerprint that survives rename/move, merge of concurrent edits, and optional write-back of marks and annotations into the PDF as standard annotations (off by default, with a backup).
- **Resource limits by design.** Built for an 8 GB MacBook Air and a Pro-plan subscription: analysis runs on demand, one Claude process at a time, memory measured against a 400 MB budget on a 600-page synthetic PDF.
- **Word export from the user's own template.** [`LelePdf/Rewrite/Export/`](LelePdf/Rewrite/Export/) writes `.docx` with a minimal ZIP writer, mapping each line type to the template's real styles by id or by name.

More detail in [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md).

## Running it

Requirements: macOS 26 on Apple Silicon, Xcode 26 (Swift 6), [XcodeGen](https://github.com/yonaskolb/XcodeGen) (`brew install xcodegen`), and the Claude Code CLI installed and logged in (`claude auth login`).

```bash
scripts/build.sh              # generate the project with XcodeGen and build (Debug)
scripts/build.sh Release      # same, Release configuration
scripts/test.sh               # unit and integration tests against the fake CLI
scripts/run.sh path/to/file.pdf
```

`LelePdf.xcodeproj` is generated from `project.yml` and is not committed. Tests that need the author's private test PDFs (two copyrighted case studies and reports) skip themselves when the files are not present.

> **Privacy note:** for analysis and chat, the PDF text is sent to Anthropic through the Claude CLI. The app says so in the interface. Results stay on the Mac.

## Known limitations

- Scanned PDFs without a text layer cannot be analysed yet (OCR is planned, SPEC §14).
- Search uses the raw page text, so a word hyphenated across two lines may not be found.
- Personal project: no notarised builds or releases are published.
